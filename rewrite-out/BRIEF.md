# 卡片重写简报（V8 · 展示层可懂化）

## 一、这是什么

一套面试记忆卡 PWA 的卡片正文重写任务。卡片内容来自候选人的项目素材（内部笔记 / 面试官 Prompt / 预演记录），
之前是"素材原文直出 + 审核痕迹"，导致用户打开卡片看到的是"材料给的是 6 段""素材中此条仅此一句"——
**通篇在讲材料，没讲知识点本身**。

本轮目标：**每张卡三秒内能看懂它在讲什么技术决策、为什么这么做、面试怎么问。**

## 二、项目背景（发挥时必须符合，不得跑偏）

这是一个**省级**的教育/政务领域 AI 问答系统——**甲方是东部沿海经济发达大省的省级部门**（省-市-县三级数据汇聚到省级平台，county_code 是省内区县维度），（面向家长、学生、教研人员的智能问答 + 数据指标问答），
候选人担任后端/架构 + 交付管理角色。

**省级项目意味着什么（所有专家视角的共同前提）**：
- **规模**：覆盖全省所有区县，数据量大、并发高——素材里的真实规模数字（50 万件/年、290 表 / 2,175 列、15 个向量库、50 万级评测样本量级）都是这个体量的体现，不要按单城市小系统想象。
- **监管层级高**：省级平台直面省级审计与行业监管，审计留痕、留存期限、fail-closed 是硬要求，不是"最佳实践建议"。
- **验收严格**：G1–G10 上线门禁、评测集甲方主导（被评方碰不到尺子）、口径必须有人拍板——省级验收不可能"先上线再补"。
- **多方关系复杂**：省级甲方 + 承建方 + 运维方 + 数据提供方（市县教育局）多方协作，口径争议、责任边界、SLA 是常态话题；合同条款、验收清单是重要依据。
- **东部沿海发达省份**：信息化基础好、甲方要求高、预算相对充足但管理精细（人力基线按人日对账、准备金、双计量），"反正糊弄一下能上线"的想象不符合这个背景。已确定的项目事实：

- **检索架构**：RAG 三路检索（向量 + 关键词 + 图谱），MVP 只上向量 + 关键词两路，图谱列二期；
  三路分数**禁止融合**（不可比），先合并去重再统一重排。
- **存储双选**：Milvus + pgvector 双选，**禁止单一向量库方案**（防环境锁死 / 私有化部署要求）。
- **重排**：BGE-reranker-v2-m3 **本地化部署**，禁用商用/外部重排 API（数据不出域）。
- **网关**：网关定位为控制点非透传（52 场景 100% 经网关）；配额校验**前置同步**、审核与计量**异步**，
  网关额外时延 P99 ≤ 30ms；AI-602 **county_code + apply_year + 学段三键锁定是过滤不是检索**。
- **审核**：审核三级串联，输入 ≤200ms / 输出 ≤300ms；提示词 100% 入库带版本（硬编码数 = 0）。
- **合规红线**：越权召回 **0 次**（写死 0，不写 ≤1%）；审计写入失败**fail-closed**（阻断调用）；
  引用与审计不可带病返回；no_hit 一律强制拒答；查询侧原文不落库用 query_hash；
  上下文组装必须二次复核权限与口径。
- **上线硬门槛 G1–G10**：G1「AI 结论 = 0」不给结论（一票否决，不允许整改后复验）；
  G9 首批 ≥50 个指标全部已审批才开问答入口；门槛不满足整体不上线、无例外。
- **数据红线**：行级隔离谓词网关注入；原文不落库；身份可去标识；留存有期限。
- **权限与授权**：授权四项用途；显式 + 隐式双标识；对象矩阵登记 top_k 区间。
- **特殊场景**：未成年人识别与转介；家长申诉入口 + SLA 追踪；教研人力合同化；合同条款只增不改。
- **指标问答**：语义层（指标定义唯一口径）；UNSUPPORTED 显式拒答（口径未登记就不答）；
  不为个性化与画像（AI-410 数据问答线）。
- **交付治理**：M 线管理决策（结构不变量验收替代评审通过、越权负样本 ≥50 条为上线前置等）；
  D 系列需求文档；ISSUE-xxx 为整改单编号。
- **失败模式词汇**：fail-closed / fail-open 按场景分级（审计、配额必须 fail-closed）。

## 三、重写规则（硬约束）

### 必须做

1. **删掉所有"材料 / 素材 / 文档 / 原表 / 附录 U / 登记行"这类指代**——这些是素材作者的内部口吻。
   正确做法：把指代直接改成陈述。
   - 错：`材料给的是 6 段` → 对：`分为 6 段`
   - 错：`材料侧对应：网关额外时延 P99 ≤ 30ms` → 对：`生产实践：网关额外时延 P99 ≤ 30ms`
   - 错：`素材中此条仅此一句，未做展开` → 对：**补写内容**（见下条）
2. **内容不足时合理发挥**——用户已授权：只要**技术解释得通、符合现实和上面的项目背景**，就可以写。
   发挥的落点通常是：
   - 这条约束**解决什么问题**（为什么必须这么做）
   - **具体机制**是怎么实现的（用行业通用做法 + 本项目背景推导，不要凭空造具体数字）
   - **不这么做会怎样**（故障场景）
   - **面试会怎么问**（3~5 个）
3. **保留并突出所有真实的数字和编号**（P99 ≤30ms / 0 次 / ≥50 条 / 100% / AI-602 / G1 / R21 等）——
   这些是面试时的硬资本，一个都不能丢，但要放在解释性文字里，不要裸列。
4. **保留卡片原有的段落结构**：
   - K 卡：`【项目位置】【当时约束】【选择与取舍】【不这么选会怎样】【面试官会从哪追问】【一句话记忆钩子】`
   - X 卡：`【简历位置】【技术要点】【生产实践】【面试官会从哪追问】【记忆钩子】`
   - T1 卡：`## 它是什么 / ## 为什么这么做 / ## 面试会怎么问 / ## 关联的完整决策`
   - 结构一个都不能少、标题文字不能改。
5. **正文中出现的项目编号**（AI-201、M23、G1、R21、ISSUE-151 等）**保留**，它们是知识的一部分。

### 禁止做

1. **禁止编造素材里没有的具体数字**（如自造"QPS 5000""延迟 12ms"）。
   需要量化时，用素材已有的数字；没有就写定性描述（"显著增加""不可接受"）。
2. **禁止伪造项目事实**（编一个素材里没有的决策、事故、客户名）。
3. **禁止写审核痕迹**：定位说明 / 最长公共子串 / 互证匹配 / 锚点 / 溯源 / 该知识点属于 X 档 /
   素材未展开（作为结论）/ 关联卡暂无 / 出处：某某文件。
4. **禁止输出"以上为上下文推断"这类自我标注**——发挥内容自然融入讲解即可，
   发挥部分的清单由主会话记录在别处，不进卡片。
5. **禁止删减素材原有的实质内容**（真实数字、真实决策、真实追问条目）。
6. 禁止改变卡片的 `id`、`title`、关联卡字段。

### 文风

- 用**工程师讲决策**的口吻：先说问题，再说选择，再说代价。
- 短句为主，一段一意。不要用"值得注意的是""综上所述"这类作文腔。
- 每张卡正文建议 250~600 字（原素材长的可以保留更长，不强行压缩）。

## 四、输出格式（严格遵守）

写 JSON 数组到指定输出文件，每个对象两个字段：

```json
[
  {
    "id": "K-02",
    "answerMarkdown": "重写后的完整正文（Markdown，含全部段落标题）"
  }
]
```

- 只输出你负责的那批卡，**不要多写也不要少写**。
- `answerMarkdown` 内换行用 `\n`，写文件时用 `JSON.stringify(arr, null, 2)`。
- 不要写任何解释性前言到 JSON 里，JSON 必须能被 `JSON.parse` 直接解析。

## 五、素材在哪里

- `source/` 目录下 7 个 md 是全部素材，可用 grep / Read 查阅（**只读，不要改**）。
- 卡片现状在工作文件里（`rewrite-out/work-groupN.json`），字段：`id / title / questions / answerMarkdown / related`。

## 六、判断标准（自测）

重写完，自问三个问题，任一答"否"就继续改：
1. 一个不了解这个项目的技术面试官，三秒内能看懂这张卡在讲什么决策吗？
2. 卡片里还有"材料 / 素材 / 文档"这类莫名其妙的指代吗？
3. 素材里的真实数字和编号，全都还在吗？
